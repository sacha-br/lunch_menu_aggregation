# 🍴 Минск Обеды: Агрегатор обеденного меню

Автоматизированный бессерверный агрегатор комплексных обедов (ланчей) в Минске из популярных заведений. Проект работает полностью автономно, собирает данные каждое утро по будням и обновляет веб-страницу на GitHub Pages **напрямую через артефакты сборки**, не засоряя историю коммитов.

👉 **[Смотреть меню на сегодня](https://sacha-br.github.io/lunch_menu_aggregation/)**

---

## 🚀 Как это работает (Архитектура)

Проект использует концепцию **Jamstack** и работает без постоянного бэкенда:
1. **Триггер:** Каждый будний день в 10:15 по Минску (07:15 UTC) GitHub Actions запускает рабочий процесс по расписанию (`cron`).
2. **Парсинг (`lunch_parser.py`):** Скрипт обходит сайты ресторанов, собирает названия блюд, описания, цены, вес и формирует файл базы данных `all_lunch_menus.json`.
3. **Генерация (`html_make.py`):** Python-скрипт инжектирует собранный JSON в HTML-шаблон и создает готовую страницу `view_menu.html`.
4. **Деплой:** Файлы упаковываются в изолированный артефакт и публикуются на GitHub Pages напрямую через API. История вашей ветки `main` остается идеально чистой.

## 💻 Локальный запуск и разработка

Если вы хотите протестировать парсеры или изменить дизайн страницы локально на своем компьютере:

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com
   cd ИМЯ_РЕПОЗИТОРИЯ
   ```

2. **Установите зависимости:**
   ```bash
   pip install requests beautifulsoup4
   ```

3. **Запустите сбор данных:**
   ```bash
   python lunch_parser.py
   ```
   *После этого в корне появится файл `all_lunch_menus.json`.*

4. **Сгенерируйте веб-страницу:**
   ```bash
   python html_make.py
   ```

5. **Проверьте результат:**
   Откройте созданный файл `view_menu.html` в любом браузере.

## ⚙️ Настройка репозитория для работы GitHub Pages

Чтобы пайплайн мог успешно публиковать сайт без коммитов, репозиторий необходимо переключить в режим экшенов:
1. Перейдите в **Settings** (Настройки репозитория) ➔ **Pages**.
2. В разделе **Build and deployment** найдите выпадающий список **Source**.
3. Обязательно выберите **GitHub Actions** (вместо *Deploy from a branch*).
